## 5. Remaining gaps for `egyptian-v2`

`recommendAuthoringTargets()` on the current profile returns **no targets** —
every member and cell is populated. So the next version's work is depth and
realism, not cells:

1. **Handoff depth, not breadth.** 619 `NOT_REQUIRED` cases is the right
   weight, but only a subset are *observed* unnecessary handoffs at baseline
   (see the v1.0 `FINDINGS.md`). `egyptian-v2` should add
   `UNNECESSARY_HANDOFF` cases whose *surface* specifically triggers the
   current classifier's booking-word shortcut, and pair each with its
   clarification-correct counterpart.
2. **Provider coverage.** The dataset has exactly one named provider
   (`د. منى`, plus `د. أحمد` in one scenario). A multi-provider tenant with
   gender/specialty variation would make `CHANGES_PROVIDER` and
   `CLARIFY_PROVIDER` genuinely discriminative.
3. **Vertical breadth.** Every case runs against a dental clinic or two small
   counter-tenants. A second vertical (salon, physiotherapy, law office) would
   prove the engine is vertical-agnostic rather than dental-tuned.
4. **Long conversations.** Only 23 `LONG_MULTI_TURN` cases. `TOPIC_RETURN`
   (18) and `LONG_CONTEXT` (64) sit almost entirely on one scenario family;
   add independent long journeys (support threads, multi-day resumption).
5. **`NO_FAQ` is thin (10 cases)** and is the only requirement kind whose
   tenant is `EMPTY_KNOWLEDGE_CONTEXT`. Add empty-tenant variants of the top
   FAQ shapes (hours, location, insurance) so the honest-gap behavior is
   measured per shape.
6. **Speech-to-text authored depth (18 cases).** Dictation noise is the
   fastest-growing input modality and is currently mutation-generated; author
   30+ dictated variants with Egyptian filler vocabulary and run-on clauses.
7. **The `INTERRUPTION` edge (6 cases)** is structurally important (a pause is
   not a human request) and should carry more register/noise variety.
8. **SELF-IMPROVEMENT CLOSURE.** 123 cases record a gap. `egyptian-v2` should
   author the derived regression cases for the gaps a human actually resolved
   (the `REGRESSION_CASE_DERIVED` stage of the schema), which is how the loop
   proves a gap can never silently reopen.
