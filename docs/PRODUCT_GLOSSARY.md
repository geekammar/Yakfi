# FlowPilot — Product Glossary

> Canonical project terminology. Use these terms (and their Arabic labels) in
> code, UI copy, and documentation. Do not invent synonyms.
> All decided terms (DECISIONS #30–#36) are IMPLEMENTED (record:
> DECISIONS #38). Last updated: DOC-NORMALIZE-V029.

| Term                    | Arabic              | Definition                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Business**            | المنشأة             | The commercial tenant of FlowPilot: one appointment-based company with its own services, team, customers, conversations, and appointments. The tenant boundary is `businessId`; Branch is selective operational scoping (DECISIONS #30).                                                                        |
| **Branch**              | الفرع               | An operational unit inside a Business. Every Business gets a **Default Branch** automatically; the current UX is effectively single-Branch. Branch-aware only where operationally meaningful (Conversation, Appointment, operational availability, WhatsAppConnection). (DECISIONS #30, IMPLEMENTED #38) |
| **WhatsAppConnection**  | اتصال واتساب        | First-class entity representing the Business-owned WhatsApp identity: `businessId` required, `branchId` optional. Default pilot model: one Default-Branch-scoped connection; Business-shared connections stay possible. (DECISIONS #31, IMPLEMENTED #38; managed via `/settings/whatsapp`) |
| **Provider**            | مقدّم الخدمة        | A bookable capability/profile — a minimal `ProviderProfile` attached to a User. NOT an authorization role (roles stay ADMIN/STAFF). (DECISIONS #32, IMPLEMENTED #38)                                                                                                                                            |
| **ProviderService**     | أهلية الخدمة        | The lightweight Provider↔Service eligibility relation (which Providers can deliver which Services). (IMPLEMENTED #38)                                                                                                                                                                                          |
| **ProviderBranch**      | أهلية الفرع         | The lightweight Provider↔Branch relation (a Provider may work in multiple Branches). (IMPLEMENTED #38)                                                                                                                                                                                                         |
| **Customer**            | العميل              | An end customer of a Business — the person whose WhatsApp messages become bookings. Unique within a Business by phone number. Business-level (never Branch-owned by default).                                                                                                                                   |
| **Conversation**        | المحادثة            | The WhatsApp thread between a Business and one Customer inside FlowPilot. Carries exactly one status (see below).                                                                                                                                                                                               |
| **Conversation Engine** | محرك المحادثات      | The implemented engine (PROMPT-19): inbound message → resolve business/customer/conversation → persist → typed AI turn → reply or NEED_HUMAN → deliver. Provider-neutral; never books appointments itself.                                                                                                      |
| **MessageTransport**    | نقل الرسائل         | The provider-neutral outbound delivery seam (DECISIONS #29) — the Meta WhatsApp Cloud API adapter is the live production implementation (DECISIONS #42/#46); the offline logging adapter stays wired behind the seam for dev/offline.                                                                          |
| **Message**             | الرسالة             | One immutable entry in a Conversation. Sender is `CUSTOMER`, `AI`, or `STAFF`. Messages are never edited or deleted.                                                                                                                                                                                            |
| **Appointment**         | الموعد              | A booking linking one Customer to one Service at a date/time, with at most one Provider (IMPLEMENTED #38) and optional staff assignment. Follows the status lifecycle `PENDING → CONFIRMED → COMPLETED` with `CANCELLED` / `NO_SHOW` exits.                                                                   |
| **Service**             | الخدمة              | A bookable offering of a Business (name + duration in minutes). Business-level; provider eligibility comes from ProviderService. Only active services can be booked.                                                                                                                                            |
| **Admin**               | مدير                | Business owner-level user (`ADMIN`). Full control: business setup, services, knowledge, team management, all conversations.                                                                                                                                                                                     |
| **Staff**               | موظف                | Employee-level user (`STAFF`). Works their own agenda and assigned conversations. No business settings or team management.                                                                                                                                                                                      |
| **Platform Operator**   | مشغّل المنصة        | The Founder / Super User as a **platform-level identity** — provisions Businesses and invites initial Admins. NOT a Business User and NOT a `UserRole` value; Founder Side UI arrives in Spec B.                                                                                                                |
| **Invitation**          | دعوة                | FlowPilot domain concept (separate from Better Auth): a request to join one Business as `ADMIN` or `STAFF`. Lifecycle `PENDING → ACCEPTED → ACTIVATED` (with `EXPIRED` / `REVOKED` exits). **Implemented end-to-end (service layer + `/invite/[token]` UI + team invitation creation).**                        |
| **Account Activation**  | تفعيل الحساب        | An invited user setting a password after acceptance, creating the Better Auth identity and the Business membership (moving from `INVITED` to `ACTIVE`). **Implemented for BOTH roles (ADMIN and STAFF).**                                                                                                       |
| **Business Activation** | تفعيل المنشأة       | The Business becoming operational after its initial Admin completes onboarding (the onboarding wizard is implemented; the formal `PROVISIONED → ACTIVE → DEACTIVATED` lifecycle states remain planned).                                                                                                         |
| **Need Human**          | يحتاج تدخلاً بشرياً | Conversation status (`NEED_HUMAN`) meaning the AI paused and requires a staff member to take over. Mandatory hand-off path — see DECISIONS.md #03.                                                                                                                                                              |
| **AI Active**           | المساعد الذكي نشط   | Conversation status (`AI_ACTIVE`) meaning the assistant is managing the thread autonomously within policy.                                                                                                                                                                                                      |
| **Booked**              | محجوز               | Conversation status (`BOOKED`) meaning the conversation produced a confirmed appointment. Thread stays for context/history.                                                                                                                                                                                     |
| **Incomplete**          | غير مكتملة          | Conversation status (`INCOMPLETE`) meaning intent existed but booking was not completed (customer dropped off or data missing).                                                                                                                                                                                 |
| **No-show**             | لم يحضر             | Appointment status (`NO_SHOW`): customer confirmed but did not attend. Tracked as ROI evidence.                                                                                                                                                                                                                 |
| **Completed**           | مكتمل               | Appointment status (`COMPLETED`): service delivered successfully.                                                                                                                                                                                                                                               |

## Related System Terms

| Term                 | Definition                                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Spec A**           | Current frozen scope: Discovery Foundation + Booking Core. See `SPEC_A.md`; sequence in `ROADMAP.md`.                                                             |
| **Vertical**         | A category of appointment-based business (dental, beauty, coach, gym, education, service). FlowPilot itself remains vertical-agnostic during discovery.           |
| **Pilot**            | A real Business using FlowPilot under the discovery strategy; success evidence source.                                                                            |
| **Need Human queue** | Dashboard/staff-workspace surface listing all `NEED_HUMAN` conversations awaiting staff action.                                                                   |
| **Usage**            | What a customer actually consumed (messages, conversations, AI runs…). Never conflated with cost, price, entitlement, or billing (`ECONOMICS.md`, DECISIONS #36). |
| **Cost-to-serve**    | What serving a customer's usage cost us (AI, WhatsApp/provider, infrastructure). Metering is current foundation; `ECONOMICS.md`.                                  |
| **Entitlement**      | What a customer is allowed to consume under their plan version (future: Plan → PlanVersion → Entitlements; never hard-coded in business logic).                   |

Language rule: UI copy uses the Arabic column; code identifiers use the
English term (e.g., enum `NEED_HUMAN`, model `Appointment`).
