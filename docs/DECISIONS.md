| 24  | PROMPT-05 | **ADMIN account activation consistency model (binding):** One-time activation is represented by `Invitation.activatedAt` (nullable timestamp, set exactly once by the atomic conditional guard in `InvitationRepository.activateInvitedAdmin` — the smallest additive schema change; no status enum, consistent with the derived lifecycle). Better Auth identity creation (`auth.api.signUpEmail` behind an injectable dependency) and the FlowPilot domain write (invitation mark + Business ADMIN membership in ONE Prisma transaction) are two sequential atomic phases — no shared transaction is attempted (not supported through the installed Better Auth version's public API; distributed transactions/sagas/queues are forbidden by ARCHITECTURE). An interruption between phases is RECOVERABLE, not compensated: the invitation stays unactivated while the identity holds zero privileges (no membership, no platform marker), and a retry resumes idempotently. One identity per email is enforced at the workflow layer: existing identities are never duplicated, never password-reset, and never silently moved or promoted — same-Business ADMIN resumes, never-assigned identities (businessId null) attach, other-Business users and same-Business STAFF get a typed `ACCOUNT_CONFLICT`.
